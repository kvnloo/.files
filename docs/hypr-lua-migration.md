# Hyprland Lua migration: tests, nested E2E, and rollback

The candidate Lua config lives at `config/hyprland/hyprland.lua`. Login still
selects `config/hyprland/hyprland.legacy.conf` until an independent reviewer
APPROVE and a human-gated compositor restart. Workers do not restart the live
compositor from this tree. Never use workspaces 1, 2, or OBS workspace 8.

## What migrated

- Static inventory: `config/hyprland/lua-ownership-map.json` and
  `config/hyprland/lua/*.lua` (`hl.config`, `hl.monitor`, `hl.window_rule`,
  `hl.bind`, plugins, autostart).
- Dynamic sources: `config/hyprland/lua/bridges.lua` plus generated
  `lua/generated/{liquid_glass,monitors}.lua` and `~/.cache/wal/colors-hyprland.lua`.
- Runtime helpers keep `hyprctl output create/remove` plus `hyprctl keyword`
  monitor/workspace/windowrule (`scripts/gui-e2e-display.sh`,
  `scripts/phone-display.sh`). Nested Lua rejects `hyprctl keyword` with
  `keyword can't work with non-legacy parsers. Use eval.` — that conversion
  error is the sabotage signal; output add/remove still works. Do not restart.

`monitors.conf` remains generated by persist-monitor-layout and is not
hand-edited. Generated Lua monitors are not applied at startup.

## Tests

Static / conversion:

```sh
python3 -m pytest tests/test_hypr_lua_e2e_lifecycle.py tests/test_hyprland_lua_migration.py -q
scripts/check-hypr-lua-parity
scripts/prove-hypr-lua-conversion-sabotage
Hyprland --verify-config -c config/hyprland/hyprland.lua
```

`scripts/prove-hypr-lua-conversion-sabotage` copies Lua owners, sabotages
representative monitor, window, bind, and source conversions, and proves
`scripts/check-hypr-lua-parity` reports `parity mismatch` (and the copy is
restored). Live files and the compositor are untouched.

Isolated nested compositor (workspace 99 / headless output, never WS1/2/8):

```sh
scripts/prove-hypr-lua-isolated-parity
scripts/prove-hypr-lua-e2e-lifecycle
```

`scripts/prove-hypr-lua-e2e-lifecycle` starts nested Lua Hyprland, exercises
`gui-e2e-display.sh` and `phone-display.sh` add/remove/recover outputs, sabotages
monitor/window/bind/source keywords against that instance, proves
`scripts/hypr-lua-config rollback`, then asserts nested PID/socket and the host
headless output are gone.

## Rollback

Atomic file selection only (`ln -sfn`). The selector never reloads or restarts
Hyprland:

```sh
scripts/hypr-lua-config rollback
```

That reselects `config/hyprland/hyprland.legacy.conf` as
`~/.config/hypr/hyprland.conf`. Activation (`scripts/hypr-lua-config activate`)
is one atomic symlink change after independent reviewer APPROVE; a live
inotify reload under the hyprlang provider will error until a human-gated
restart, so workers must not activate or restart.

Safe checkpoints: `23dbfc3`, `cb919a8`, controller `a703c95`.
