# HRE phone sweep: the phones label every owner message

The History Research Engine (`operations/history-research-engine-20261118`) needs an exhaustive
first pass over every owner message. Agents stop after one or two hits, so the phones do it:
local small models label each message, and Opus agents verify afterwards.

- **Code:** `services/hre-phone/`
- **Manifests:** `config/k3s/manifests/62-hre-phone-sweep.yaml` and `62-hre-phone-code.yaml`
  (generated by `services/hre-phone/render-configmap`)
- **Pods:** namespace `phones`, node `mbp`. They are thin HTTP drivers. The models run natively on
  the phones as `llama-server` under `adb shell` (no app, no install). Owner text goes only from the
  pod to a phone over the tailnet; it never goes to a cloud API.

## Pieces

| Piece | Where | What |
|---|---|---|
| `build_corpus.py` | groot | Builds `corpus/owner-msgs.jsonl` (id, source, profile, ts, iso, text) from T1's `t1/owner.jsonl`. Drops pasted capsules and task bodies (text starting with `[` or `# Kanban`) and exact duplicates. |
| `make_calib.py` | groot | Builds a 200-row stratified calibration set `corpus/calib/calib-200.jsonl`. Opus labels it as `gold-opus.jsonl`, using Claude only. |
| `hre_slm_server.sh SERIAL PORT MODEL [args]` | groot/mbp with adb | (Re)starts a llama-server on a phone under `/data/local/tmp/hre-slm`, with the llama.cpp b12527 Android build and an API key. The phone's own `shadow-<dev>` server on :8080 is left alone. |
| `phone_label.py` | pod / anywhere | One message in, `{flag, p_flag, cue, concepts, ask}` out. Modes: `full` and `flag` use chat completions with a JSON-schema grammar and logprobs for `p_flag`. `d1` uses the Liquid d1 `/v1/systemone` decision endpoint, which gives a calibrated P(yes). |
| `phone_sweep.py` | pod `hre-label-<phone>` | Work-stealing sweep. The corpus is cut into 100-row chunks. A worker claims a chunk with an atomic `O_EXCL` claim file and writes `sweep/<job>/out/<chunk>.jsonl`. **A chunk is done only when its out file has a row for every id.** A claim with no progress for 15 min is taken over and resumed. |
| `phone_embed.py` | pod `hre-embed-tab` | Embeds the corpus with Qwen3-Embedding-0.6B on the Lenovo tab into `embeddings/emb-tab.jsonl`, for T3 concept clustering. |
| `assemble_labels.py` | CronJob `hre-assemble` (every 10 min) | Joins both sweeps into `/data/phone-labels.jsonl`, one row per id. Final flag = d1 `p_flag >= 0.10`, falling back to the LFM3 flag until d1 reaches the row. Appends a coverage and per-worker rows/hour line to `/data/coverage.jsonl`. |
| `score_calib.py` | groot | Compares each candidate with the Opus gold labels. Reports flag recall, precision, AUC, the threshold that reaches recall ≥ 0.9, and concept precision and recall. |

## Crash restarts

On the S25, b12527's HTP backend sometimes aborts with `ggml-hex: dspqueue_read failed: 0x68`. The shadow-s25 b11759 server does the same.

`hre_slm_server.sh` therefore runs llama-server under an on-phone supervisor (`hre-sup.sh`):
- It restarts the server only after a crash signal (rc 132/134/135/139), at most 30 times in a row. Each exit is logged to `server-PORT.exits`.
- Any other exit ends the supervisor. That includes SIGTERM from `phone-worker off` and lmkd's SIGKILL, so the owner switch still stops the server.

## Owner gates

`phone_sweep.py --gate` re-implements phone-worker's `gate()` over adb every 10 rows:
- **S22:** works only when not in a call.
- **S25:** works only when not in a call and the owner has been idle for at least 120 s.

adb in the pod is platform-tools (glibc only), mounted from mbp `~/.local/share/hre-phone/platform-tools`. The key is the Secret `phone-adbkey`. The pod runs its own adb server on port 5047.

The S25 off switch (`~/.local/state/s25-worker-off` on groot) works through `phone-worker off`: its wind-down kills every `llama-server` on the S25, and the sweep never restarts a server.

## Data

The data lives at `/home/kvn/hre-phone` on mbp (mode 700). The pods mount it at `/data`.

- `owner-msgs.jsonl` is copied from groot.
- Results are pulled back to `corpus/` on groot.
- The phone SLM API key is the Secret `hre-phone-slm-key`. Create it with
  `kubectl create secret generic hre-phone-slm-key -n phones --from-file=key=$HOME/.local/state/phone-native-inference/api-key`.
  It is never committed.

## Rules (home-k3s-fleet)

- No battery, temperature or RAM admission gates.
- S25 worker mode respects `~/.local/state/s25-worker-off`.
- No adb pushes or installs during the owner's focus or sleep windows.
- No agent work on groot. The drivers run in k3s on mbp.
